1. What you are setting up

PieceWhereNeeds
Website src/ — Next.js on Vercel A read-only database login and the bucket's public URL
App packages/app/ — Tauri (Rust + React) A writing database login and the bucket's write key, compiled into the build
Database Neon Postgres — its own project, separate from booru Three logins: owner, collecto_app, collecto_web
Images One Cloudflare R2 bucket, public-read An API token for the app, a public domain for everyone

2. Tools to install

  • Node.js 24 or later (npm 11 comes with it).
  • Rust, stable, via rustup. On Windows use the MSVC toolchain, which needs Visual Studio Build Tools with the “Desktop development with C++” workload.
  • WebView2 — already on Windows 11. Only needed for the app.
  • Git.

No CMake or NASM is needed; the dependencies are chosen to avoid them.

git clone https://github.com/phumoonlight/collecto.git
cd collecto
npm install

3. Neon database

  1. Create a new project at console.neon.tech. It comes with an owner role neondb_owner — that owner is your DATABASE_URL_OWNER.
  2. Create the database Collecto uses, app, owned by neondb_owner: in the console under Databases → New database, or in the SQL Editor with create database app owner neondb_owner;. The default neondb is left unused.
  3. Open the SQL Editor and create the other two roles there, with long random passwords (roles belong to the branch, not to one database, so either database can be selected): 
    create role collecto_app login password 'a long random string';
create role collecto_web login password 'a different long random string';
  4. From Connect, pick database app and copy the connection strings — every URL must end in /app?sslmode=require…, not /neondb. Neon offers a pooled host (contains -pooler) and a direct host. Swap in each role's user name and password.
Do not use the console's “Add role” button. A console-made role is a member of neon_superuser, which overrides every grant — collecto_web could then write anything — and the owner cannot revoke it. If you did, drop role and make it again with SQL.

4. Cloudflare R2 bucket

  1. In the Cloudflare dashboard, open R2 and create a bucket, e.g. collecto.
  2. Make it publicly readable: under the bucket's Settings → Public access, connect a custom domain (e.g. img.example.com), or enable the r2.dev URL for testing. That origin is NEXT_PUBLIC_CDN_URL.
  3. Create an API token under R2 → Manage API tokens with Object Read & Write, limited to this bucket. Note the Access Key ID and Secret Access Key — the secret is shown once.
  4. Your Account ID is on the R2 overview page.

The app writes collections/posts/<md5>.<ext> and collections/thumbs/<md5>.<ext>, each with a one-year immutable cache header.

5. .env

Copy the template and fill it in. It is git-ignored, and it is the one file the website, the migration runner and the app build all read. 

cp .env.example .env
VariableValueUsed by
DATABASE_URL collecto_web on the pooled host website
DATABASE_URL_APP collecto_app, direct host (pooled also works) app build
DATABASE_URL_OWNER neondb_owner migrations only
NEXT_PUBLIC_CDN_URL bucket's public origin, no trailing slash website, app
R2_ACCOUNT_ID, R2_ACCESS_KEY_ID,
R2_SECRET_ACCESS_KEY, R2_BUCKET		 from step 4 app build
NEXT_PUBLIC_SITE_URL the website's origin, e.g. https://collecto.example.com website (optional), app
NEXT_PUBLIC_SITE_NAME display name, default Collecto website

Neon's strings may end in &channel_binding=require; that is fine for both sides. Keep sslmode=require.

6. Create the tables

npm run db:push      # lists pending migrations, asks, applies, then applies the grants
npm run db:list      # what is applied and pending
npm run db:reset     # start over: drops every table, re-applies everything

db:reset deletes every collection and image row. It lists what it will drop and asks you to type the database name (app) before doing anything. Images already uploaded stay in the bucket as orphans — empty the bucket's collections/ prefix in the Cloudflare dashboard if you want a truly fresh start.

Run db:push again whenever you recreate a role — it re-applies db/grants.sql every time, even with no new migrations. If it says a role “does not exist — skipping its grants”, step 3.2 was missed.

7. Run the website

npm run dev          # http://localhost:3000
npm run build        # production build
npm run lint
npm run typecheck    # run `npx next typegen` first on a fresh checkout

Without DATABASE_URL every page shows a “database is not configured” notice instead of failing. A new board is empty — the collection list only shows collections that hold images, so add some with the app first.

8. Run and build the app

npm run app:dev      # the window, with hot reload
npm run app:test     # Rust tests
npm run app:build    # release build + NSIS installer
  • The board's values are compiled in from .env (or the process environment) by packages/app/src-tauri/build.rs. After changing them, rebuild.
  • A debug build without them still opens, on the Settings screen saying it is not set up. A release build refuses to compile and names what is missing.
  • The installer lands in packages/app/src-tauri/target/release/bundle/nsis/.
  • Preferences live in save.json (Settings → Open data folder); the cache and log in app-cache/. Debug builds keep their own copies under a dev folder.
The installer contains the writing database login and the bucket key. Anyone who has it can change the board. Share it only with people you would give those credentials to. To revoke, change the collecto_app password and rotate the R2 token, then rebuild.

9. Deploy the website to Vercel

  1. Import the repository in Vercel. Framework: Next.js; root directory: the repo root.
  2. Set environment variables: DATABASE_URL (pooled, collecto_web), NEXT_PUBLIC_CDN_URL, NEXT_PUBLIC_SITE_URL, and optionally NEXT_PUBLIC_SITE_NAME.
  3. Do not add DATABASE_URL_APP, DATABASE_URL_OWNER or any R2_* — the website never writes.
  4. Node.js 24 is required (engines in package.json). The region is sin1 (vercel.json).
  5. Optionally enable Web Analytics and Speed Insights; both are already wired in.

10. Troubleshooting

SymptomCause and fix
DATABASE_URL_OWNER is not set .env is missing or not at the repo root.
Website gets permission denied Grants not applied to collecto_web — run npm run db:push.
Website can write tables it should not The role was made with the console button. Drop it, recreate with SQL, db:push.
App opens on Settings: “no board baked into it” Values were missing at build time. Fill .env, rebuild.
Upload fails with 403 SignatureDoesNotMatch / InvalidAccessKeyId Wrong R2_* values, or a token not scoped to this bucket.
Images upload but don't show The bucket has no public access, or NEXT_PUBLIC_CDN_URL points elsewhere.
“Could not reach the database (timed out)” No network, or a suspended Neon compute still waking up — try again.
Rust build fails linking on Windows Visual Studio Build Tools with the C++ workload is missing.
npm install warns about install scripts npm 11 blocks unlisted scripts; approve the package in allowScripts in package.json.
