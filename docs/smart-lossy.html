Smart lossy compression

A planned option, not built yet: make PNG uploads much smaller by changing their pixels slightly, the way TinyPNG does. It sits next to today’s lossless compression and is off unless you turn it on.

Today vs. smart lossy

Today (lossless)Smart lossy (optional)
PixelsIdentical to the upload, checkedChanged slightly
PNG size savingUsually smallOften 50–80%
Best forEverythingFlat art, screenshots, icons
Bad for—Photos, smooth gradients (colour banding)
Original kept?YesNo — only the smaller file is stored
DefaultOnOff

Lossy can’t be undone: once uploaded this way, the original pixels are gone. That is why it is a choice you make, never the default.

How it works

A PNG can hold millions of colours. Smart lossy picks the best 256 for the picture and redraws it with only those, blending (dithering) where colours meet so the eye doesn’t notice. Fewer colours compress far better.

Every result is then compared with the original. If it looks too different, or isn’t smaller, the app throws it away and uses normal lossless compression instead — so the worst case is the same as today.

Per format

FormatSmart lossy
PNGYes — the main target
JPEGNo: re-saving a JPEG at lower quality loses detail for little gain
WebPMaybe later, for lossless WebP only
GIFNo: already 256 colours

How you’d turn it on

  • A Settings switch under Compression: “Smart lossy for PNG: off / on”.
  • Maybe also a switch on the upload screen, for one batch of screenshots only.
  • The log says when a file was stored lossy, and how much it saved.

Open question

The best colour-reduction library (imagequant, used by pngquant) is GPL-3 licensed unless a commercial licence is bought, which matters if the app is ever shared. Free-licence alternatives exist but give worse results. Technical details for the implementation are in docs/smart-lossy.md.
